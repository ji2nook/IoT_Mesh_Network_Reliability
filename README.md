## 🚀 프로젝트 소개

중앙 집중형 통신 인프라는 지진, 화재, 홍수 등의 재난 발생 시 통신망이 무력화될 수 있다는 취약점이 존재합니다. 특히 기지국이나 라우터 등 중앙 인프라 자체가 파손되면 네트워크는 그 즉시 단절됩니다. 이 연구는 직접 수행한 실험을 바탕으로 **IoT 기기들이 자율적으로 라우터로서 네트워크를 구성하는 메시 네트워크가 해당 상황에서 얼마나 신뢰성 있게 작동하는지**를 정량적으로 평가했습니다.

5대의 라즈베리파이를 노드로 활용하여 BATMAN-adv 기반 메시 네트워크를 구축하고, 두 가지 재난 시나리오에서 패킷 손실률·RTT·경로 복구 시간을 측정하였습니다. 비교군으로 정적 라우팅 네트워크의 동일 시나리오 결과를 선정하였습니다.

### 프로젝트 및 팀 정보

- **과목**: 정보통신 기초 종합 설계
- **기간**: 2026.09.14. ~ 2026.11.29.
- **팀 인원**: 3인
- **역할**: 팀장, 프로젝트 설계, 재난 상황 모사 및 BATMAN-adv 기반 메시 네트워크 통신 성능 측정 코드 구현

## 🧪 실험 설계

### 시스템 구성

| 구성 요소 | 내용 |
|---|---|
| 노드 하드웨어 | 5대의 Raspberry Pi 모델 4 (Pi1 ~ Pi5) |
| 메시 프로토콜 | BATMAN-adv (ibss ad-hoc 모드) |
| 토폴로지 강제 | `iptables` FORWARD 규칙으로 선형 연결만 허용 |
| 성능 측정 | `ping` (패킷 손실률 · RTT) |
| 노드 파손 구현 | Pi3 자동 재부팅 (90초 후 `sudo reboot`) |
| 전파 방해 구현 | `tc netem` — bat0 인터페이스 패킷 손실률 점진적 증가 (10% ~ 100%) |
| 결과 분석 | Python (`numpy`, `re`) |
| 실험 자동화 | Bash 스크립트 |

### 선형 토폴로지

```
   Pi1 ──── Pi2 ──── Pi3(브릿지) ──── Pi4 ──── Pi5
    │                                          │
측정 노드                                   대상 노드

(Pi1 → Pi5 경로 성능 측정)
```

iptables의 FORWARD 규칙으로 인접 노드 간 패킷 전달만 허용하여 5개의 노득 선형 토폴로지를 유지하도록 합니다.
Pi3가 두 그룹(Pi1, Pi2 / Pi4, Pi5)을 잇는 브릿지 역할을 합니다.

### 시나리오 1 — 노드 파손 (Broken)

```
[정상 상태]  Pi1 ──── Pi2 ──── Pi3(브릿지) ──── Pi4 ──── Pi5
                                    │
                    90초 후 재부팅 (노드 파손 시뮬레이션)
                                    │
[복구 후]    Pi1 ──── Pi2 ──────────────────── Pi4 ──── Pi5
```

Pi3가 강제적으로 재부팅하게 되어 연결에서 이탈하면, BATMAN-adv의 자가 복구를 통해 우회 경로를 새롭게 탐색합니다. Pi1에서 Pi3와의 연결이 끊긴 시점부터 Pi5까지 재연결되는 시간을 측정합니다. 비교군인 정적 라우팅은 경로 재설정 매커니즘이 작동하지 않아 복구 불가 상태로 남습니다.

### 시나리오 2 — 전파 방해 (Jamming)

```
[정상 상태]  Pi1 ──── Pi2 ──── Pi3(방해 노드) ──── Pi4 ──── Pi5
                                    │
                  10초마다 bat0 손실률 10%씩 증가 (최대 100%)
                                    │
[복구 후]    Pi1 ──── Pi2 ────────────────────── Pi4 ──── Pi5
```

Pi3의 bat0 인터페이스에 `tc netem`으로 전파 방해 상황을 점진적으로 가하고, Pi1이 연결 품질 저하를 감지하여 Pi5로의 우회 경로를 확보하기까지의 시간을 측정합니다. 비교군인 정적 라우팅은 경로 재설정 매커니즘이 작동하지 않아 복구 불가 상태로 남습니다.

## 📊 실험 결과

### 시나리오 1 — 노드 파손 (5회 반복 평균)

| 구분 | 패킷 손실률 | RTT |
|---|---|---|
| 메시 — 정상 상태 | 0.0% | 7.044 ms ± 1.003 |
| 메시 — 복구 후 | **0.0%** | **7.151 ms ± 1.068** |
| 정적 라우팅 — 정상 상태 | 0.0% | 20.890 ms ± 1.359 |
| 정적 라우팅 — 복구 후 | **100%** (통신 두절) | N/A |

- **메시 네트워크 평균 복구 소요 시간: 46 ms** (표준편차 ± 12 ms)
- **정적 라우팅: 복구 불가** (브릿지 노드 파손 시 양단 그룹 간 통신 완전 단절)

### 시나리오 2 — 전파 방해 (5회 반복 평균)

| 구분 | 패킷 손실률 | RTT |
|---|---|---|
| 메시 — 정상 상태 | 0.0% | 5.186 ms ± 0.871 |
| 메시 — 복구 후 | **0.0%** | **6.454 ms ± 0.637** |
| 정적 라우팅 — 정상 상태 | 0.0% | 19.641 ms ± 1.385 |
| 정적 라우팅 — 복구 후 | **100%** (통신 두절) | N/A |

- **메시 평균 복구 소요 시간: 28 ms** (표준편차 ± 5 ms)
- **정적 라우팅: 복구 불가** (전파 방해 노드가 유일한 경로를 점유)

### 주요 발견

메시 네트워크는 두 시나리오 모두에서 **완전한 자가 복구에 성공**하였으며, 복구 후 패킷 손실률과 RTT를 정상 상태와 유사하게 유지했습니다. 반면 정적 라우팅은 브릿지 노드에 장애 발생 시 경로 재설정이 불가능하여 통신이 영구 단절되었습니다.
